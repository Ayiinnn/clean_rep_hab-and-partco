#### 3. diagnosis 

可忽略，正在利用这些干净项目文件做一些诊断实验，尝试除直接缩小unsup尺度外的解决方法

首先确认无part分支的hab和pco标签acc几乎无差异，后期hab更高。hab标签显著尖锐，gate前pair acc差异不显著。基于此调整门控。

调整门控之后通过率几乎无差异，gate后pair acc差异仍有但不再显著。但仍然存在断崖等问题，遂展开进一步实验，列出问题清单。以下问题清单基于原始pco和调整门控后的原始尺度hab。

问题清单(恢复原始尺度1的诊断结果):
1. 不论何时，hab产生pair的结构的效果都稍差 (标签差不多甚至更准，但pair acc会稍低: 错误更容易造成异类同标签，错误有更强聚集性)
   
2. part分支在30 ep之前，为pco带来了标签准确率的细微提升，hab几乎0作用(相对无part版)
   
3. (主)hab 在30ep处，平均grad(unsup)/grad(all)与pco接近，但是一个epoch中unsup的激活频率低(这个有可能是偶然)，但单次unsup激活产生的grad(unsup)是pco三倍(这个在30ep几个batch，以及后面临近几个epoch都这样), 猜测是断崖成因。目前正在进一步拆解分析原因。

4. (主)30ep-30ep hab标签准确率pair准确率等等等等全崩了，pco gU/gA 降低至1/3(虽然大后期也会涨上来) hab gU/gA 没降。问题较多，这个留到3.解决后再看，因为很可能是断崖后果。
